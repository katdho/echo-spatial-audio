# Technical Project Summary

## Project summary

**ECHO** is a spatial-audio instrument: you place sounds in a virtual room, move them along paths around a listener, and render a binaural (headphone) stereo mix that carries the cues the ear uses to localize sound: interaural time differences, Doppler shift, distance-dependent level and brightness, early wall reflections, and a reverberant tail. It is a Python library (`src/echo/`) plus a browser control panel (`python app.py`, served from `src/echo/web/index.html`) and a notebook (`src/echo_notebook.ipynb`) that embeds the same panel. Sources can be your own recordings (loaded with `pq.Audio.from_file`), Freesound IDs, or sounds generated by a built-in Karplus–Strong plucked-string model that plugs into `pq.Score` like the instruments in the course notes. I built it as a mixing/spatialization stage for my final composition: dry layers go in, a moving, reverberant stereo scene comes out.

The technique is **delay lines, effects and spatialization (Chapter 13)**, with a **physical-model string source (Chapter 12)**. Everything is implemented from the delay-line recurrences in the notes, in NumPy only. A *time-varying fractional delay line* is the core idea: each ear reads the source at delay `r_ear(t)/c`, so the left/right difference is the interaural time difference and the rate of change of the delay is the Doppler shift. The same read-at-a-delay operation, applied at the path lengths of mirrored "image sources", gives first-order room reflections (a multi-tap delay, as in the notes' chorus). The late reverb is an 8-line feedback delay network (Hadamard feedback matrix, per-line decay gain `10^(-3M/(f_s T60))` and in-loop damping), generalizing the notes' Schroeder reverb, which is also kept as a selectable algorithm. A stereo ping-pong delay is the cross-feedback version of the notes' `ping_pong_delay`. The notes write feedback loops one sample at a time; since `y[n] = x[n] + g·y[n−M]` only depends on samples at least `M` back, I evaluate each recurrence `M` samples at a time with vector operations (verified against the notes' circular-buffer loop in `tests.py`), so a 30-second, 5-source scene renders in about six seconds.

## Requirements

1. **R1 — Technique.** The tool is built around *delay lines, effects and spatialization* (Chapter 13: fractional/time-varying delay lines, multi-tap delays, feedback delay networks, all-pass/comb reverb, ping-pong delay, panning) and *physical modeling* (Chapter 12: Karplus–Strong string). Spatialization is central: every source passes through `spatial.propagate()`, and nothing is output without it. Beyond the notes, I added moving-source binaural rendering with Doppler, image-source reflections, an FDN reverb, source trajectories (orbit, spiral, oscillate, flyby, waypoints) and a calibrated reverb send bus.
2. **R2 — Implementation.** All core DSP is my own NumPy code in `src/echo/dsp.py` (`fractional_delay`, `feedback_delay`, `allpass`, `one_pole`, `pluck`, `ping_pong`, `schroeder_reverb`, `fdn_reverb`) and `src/echo/spatial.py` (`propagate`: per-ear delay + gain + time-varying low-pass; `Room.images`; trajectories); `engine.Echo.render` wires it together. No library effect, reverb, panner or time-stretcher is used; NumPy does array math and pyquist handles audio I/O, `Audio`, `Score` and pitch helpers. `python tests.py` runs 11 checks: block-vectorized loops equal the notes' sample-by-sample loops; all-pass magnitude is flat; the measured interaural delay matches head width (≈22 samples); a flyby shifts pitch up then down (Doppler) and `doppler=0` removes it; the FDN's measured T60 matches the setting; the plucked string is in tune; ping-pong echoes alternate channels; every demo scene in the control panel builds and renders to audible stereo.
3. **R3 — Controllable.** The tool exposes many audible parameters (UI ranges in brackets; the library accepts any value):
   - **Per source:**
     - `motion` (Static / Orbit / Spiral / Oscillate / Flyby / Waypoints): path shape.
     - `x`, `y` [−15…15 m]: centre/start position; listener at the origin facing +y.
     - `radius` [0.5…40 m]: orbit radius, oscillation amplitude, spiral outer radius, or flyby half-span.
     - `speed` [−0.5…0.5 rev/s or Hz]: motion rate; positive circles counter-clockwise on the map, negative reverses it.
     - `pass_time` [1…30 s]: duration of a flyby.
     - `gain_db` [−30…+6 dB]: source level.
     - `send` [0…1]: amount sent to the reverb; far sources with high send sound "distant".
     - `doppler` [0…3]: 0 = no pitch shift, 1 = physical, >1 exaggerated.
     - `rolloff` [0…2]: distance-gain exponent (1 = inverse distance, 0 = no level change).
     - `air_absorption` [0…4]: how much distance darkens the sound.
     - `head_shadow` [0…1]: darkening of the ear facing away from the source.
   - **Room:**
     - `enabled`: reflections on/off.
     - `width`, `depth` [4…60 m]: room size; sets reflection delays (echo spacing, "small vs. large space").
     - `absorption` [0…1]: wall absorption; 0 gives bright, strong reflections.
   - **Reverb:**
     - `kind` (`fdn` / `schroeder`): algorithm.
     - `t60` [0.3…10 s]: 60 dB decay time.
     - `damping` [0…0.5]: in-loop high-frequency damping; higher is darker.
     - `size` [0.5…2.5]: scales FDN delay lengths (density/echo spacing).
     - `predelay` [0…0.2 s]: gap before the tail starts.
     - `level_db` [−30…+6 dB]: reverb return level.
   - **Ping-pong delay:**
     - `time` [0.05…1.5 s]: echo spacing.
     - `feedback` [0…0.95]: repeats.
     - `level_db` [−30…+6 dB]: echo level.
   - **Plucked-string generator** (`sources.pluck_line` / `pluck_instrument`):
     - `pitch`: note name or MIDI number.
     - `duration`: note length in seconds.
     - `t60`: 60 dB decay of the string.
     - `damping` [0…0.5]: brightness of the loop low-pass.
     - `pick_position` [0…1]: comb colour of the pluck (0 = off).
4. **R4 — Demo.** `demo.py` renders the three examples shown in the video, each with different sources and settings, plus the composition sketch, into `src/renders/`: (1) `1_doppler_flyby.wav`: dry noise ticks fly past at 3 m distance with the room and reverb off, so ITD, Doppler, level and darkening are heard in isolation (then toggle `doppler`); (2) `2_orbiting_strings.wav`: a plucked-string arpeggio orbits in a 14×11 m room with FDN reverb and ping-pong delay over a drone; (3) `3_distant_cathedral.wav`: bell-like plucks spiral through a 40×30 m room with a 7 s, dark, pre-delayed FDN tail (with `--files`, your own recording replaces the bells). The video narrates the technique with the relevant code: `fractional_delay` and `propagate` for ITD/Doppler, `feedback_delay` and its chunked evaluation, `fdn_reverb`, and `pluck`.
5. **R5 — Composition plan.** In my final composition I'll use ECHO as the spatial mixing stage for every layer: dry material (my own recordings plus Karplus–Strong strings written as `pq.Score`s) is rendered through `Echo.render()` into stereo stems, with `Waypoints` trajectories giving each layer a path that follows the form. I'll follow the arc of `4_composition_sketch.wav` (about 26 s plus tail, played in the video): a distant drone enters first, an arpeggio orbits counter-clockwise, a counter-arpeggio orbits the other way, noise ticks sweep left to right, one flyby with Doppler marks the climax, and everything dissolves into the reverb tail. Large `t60` and `size` give the open sections, a small room with the delay off gives the intimate ones, and the ping-pong delay carries rhythmic material.

## Code execution instructions

Requires Python 3.10+ and `pip install pyquist` (NumPy, `soundfile` and `sounddevice` come with pyquist). The control panel uses only the Python standard library, so nothing else is needed (`ipywidgets` and `matplotlib` are only for the optional notebook). Rendering needs no audio hardware; listening uses your browser's audio output, and **headphones are strongly recommended** because the spatial cues are binaural. From the `src/` directory:

```sh
python app.py                         # control panel: opens http://127.0.0.1:8765 in your browser
python tests.py                       # 11 DSP checks (about 5 s)
python demo.py                        # renders the 3 demos + composition sketch to renders/*.wav (about 10 s)
python demo.py --files a.wav b.wav    # same, but uses your own audio as sources in demos 3 and 4
python demo.py --play                 # also plays each render (needs an audio output device)
jupyter lab echo_notebook.ipynb       # optional: same panel inside a notebook, plus code examples
```

In the control panel: (1) pick a demo scene or click sounds to add them, then **Build scene**; (2) drag sounds on the map and use the sliders on either side; (3) press **Render and play** and watch the dots move along their paths. **Export WAV** saves the result; **Reset sliders** and **Start over** undo changes. See `DEMO_GUIDE.md` for a full walkthrough. Use the engine from code like this:

```python
from echo import Echo, Orbit, ReverbSettings, sources
e = Echo()
e.add_source("my_sound.wav", motion=Orbit(radius=3, speed=0.1), send=0.4)
e.reverb = ReverbSettings(t60=3.0)
e.render(20.0).write("out.wav")
```
